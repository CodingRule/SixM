> [!IMPORTANT]
> **SixM is pre-alpha and there is no in-game client yet.**
>
> - SixM does **not** launch, modify or contain GTA VI. You cannot play GTA VI multiplayer with it today.
> - What exists is the dedicated server, the Lua resource system, and a **headless client** (no graphics) used for
>   testing and bots.
> - The planned game integration targets the open-source Leonida runtime
>   ([Leonida Continued](https://github.com/ubiquitarianism/leonida)), which boots the game's menus from your own copy
>   but has nothing playable yet. In-game multiplayer is blocked on that. It is a roadmap item, not a feature.
> - No game files, keys or assets are in this release or in the repository, and none ever will be.

SixM 0.2.0 replaces the Node.js implementation with one written in Rust. What you run and script against stays the
same; what runs it is new.

## What changed

- **Rewritten in Rust.** The server and the headless client are now native programs. The wire protocol (version 1),
  the Lua API, `server.cfg` and `manifest.lua` are the same as in 0.1, so existing resources run unchanged, and a
  0.1 client can still join a 0.2 server. (#5)
- **Lua 5.4.** Scripts run on the reference Lua 5.4 interpreter instead of a Lua 5.3 VM written in JavaScript.
  Integers are 64-bit; the 32-bit integer limit of 0.1 is gone.
- **Script watchdog.** A script that executes 50,000,000 Lua instructions without yielding is stopped, the error is
  logged with a traceback, and the server keeps running. In 0.1 a script that looped without calling `Wait` blocked
  the server for good. (#8)
- **Small executables.** `sixm-server.exe` is about 2.3 MB and `sixm-client.exe` about 1.8 MB. The 0.1 executables
  were about 96 MB each.
- **Less memory.** A full 32-player server used about 13 MB, measured on a Windows desktop with the clients
  connecting through the LAN address. The same test on 0.1 used about 65 MB.
- **Linux build.** Releases now include executables for Linux x64 next to the Windows ones. (#11)

One behaviour to know about if you write resources: values passed between resources (event arguments, export
arguments and results) and over the network are copied through JSON. Functions and userdata arrive as `nil`, and so
do NaN and infinite numbers. An export cannot return a function, and a function cannot be passed to another resource
in an event. The callbacks the server passes to `playerConnecting` handlers (`setKickReason` and `deferrals`) still
work. Details are in [docs/scripting.md](https://github.com/CodingRule/SixM/blob/v0.2.0/docs/scripting.md#values-that-cross-a-boundary).

## Download and run

Each archive holds `sixm-server`, `sixm-client`, `server.cfg`, `LICENSE` and the `resources/` folder. Nothing else
needs to be installed.

### Windows

1. Download `sixm-0.2.0-windows-x64.zip` and extract it.
2. Open a terminal in the extracted `sixm-0.2.0` folder and start the server:

```powershell
.\sixm-server.exe
```

3. In a second terminal in the same folder, connect a headless client:

```powershell
.\sixm-client.exe --name Alice
```

The executables are not code-signed. Windows SmartScreen may show "Windows protected your PC" the first time you
run one; choose **More info**, then **Run anyway**, if you trust the download. You can check it against
`SHA256SUMS.txt` first:

```powershell
Get-FileHash .\sixm-0.2.0-windows-x64.zip -Algorithm SHA256
```

### Linux

1. Download `sixm-0.2.0-linux-x64.tar.gz` and unpack it:

```sh
tar -xzf sixm-0.2.0-linux-x64.tar.gz
```

2. Start the server from the unpacked folder:

```sh
cd sixm-0.2.0
```

```sh
./sixm-server
```

3. In a second terminal in the same folder, connect a headless client:

```sh
./sixm-client --name Alice
```

### Then

Open <http://localhost:30120/> for the status page. Type `help` in the server console for its commands, and try
`say hello` in the client. Hosting for other people is covered in
[docs/hosting.md](https://github.com/CodingRule/SixM/blob/v0.2.0/docs/hosting.md).

To build from source instead, you need a Rust toolchain (1.80 or newer) and a C compiler; see the
[README](https://github.com/CodingRule/SixM/blob/v0.2.0/README.md#quick-start).

## Known limits

- **No in-game client.** Clients are text-only.
- **WebSocket over TCP only.** There is no UDP transport yet.
- **Only player state is synced**: position, heading, velocity and a few flags. No vehicles, no entity ownership,
  no state bags.
- **The watchdog has gaps.** It counts Lua VM instructions, so one long call into a built-in function (for example
  a pathological string pattern) is not interrupted, and there is no memory limit for scripts. While a script uses
  up its instruction budget, nothing else on the server runs.
- **The Linux build has not been run on a real host.** It is built, and its tests pass, in CI. Reports are welcome.
- **More than 32 players is untested**, and so are connections from another machine or over the internet. The
  32-player measurement above was made on one machine.
- **Client-reported state is not validated** against game rules, and there are no accounts, bans or permissions.
- **The protocol and the API are not stable** and can change in any release.
